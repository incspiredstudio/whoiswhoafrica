# Import

The module that brings profiles from the acquisition pipeline into WordPress, safely, in a way that can be previewed, resumed and undone.

## Responsibility

- Validate an export bundle against the import contract.
- Show a dry run of every record before anything is written.
- Apply records in resumable chunks and report a result code for each.
- Undo a batch that has not been reviewed.
- Give acquisition a suppression snapshot and an import result, and take nothing else from it.

The pipeline never publishes and holds no WordPress credential. A named Administrator starts every import.

## Content types, taxonomies and tables

| Item | Notes |
|---|---|
| `wiw_import_batches` | Batch id, contract version, file hash, settings snapshot, status, progress cursor |
| `wiw_import_results` | Record id and result code per record. The exported result carries no field values |
| `wiw_sources` | The read-only source snapshot used by the Sources screen (shared with Directory) |
| `wiw_claims`, `wiw_passages`, `wiw_verification` | Admin-only tables for the pipeline's claim text, source passages and verification report. Never public; reduced or deleted per the retention schedule |
| Private import directory | Outside the web root, for files placed by hand and used by the command line |

The claim and passage tables above hold the pipeline's claims about facts. They are unrelated to the profile claim requests handled by the Trust module.

## Admin screens

| Screen | What it does |
|---|---|
| Import | Upload a bundle, run the dry run, see a diff and a result code per record, confirm, watch progress, undo a batch, read history |
| Sources (read-only) | Shared with Directory. Counts per source |

Command line: `php bin/wiw.php import` (or WP-CLI if the host has it). A REST import route is not built for now.

None. The module writes. Reading happens through Directory.

## Jobs, hooks and events

| Step | Behaviour |
|---|---|
| Manifest check | Known contract version, record count, and `records_sha256` over the file. A bad manifest refuses the whole bundle |
| Dry run | Validates every record without writing: schema and allowlisted fields per entity type, per-field provenance, no low-confidence or unsourced field, the verification report, the recomputed content hash against `content_hash`, the live suppression list, empty image fields, known taxonomy terms |
| Apply | An authenticated, resumable job runner applies 25 to 50 records per step (tuned on the live host). A timeout resumes where it stopped |
| Result codes | `CREATED`, `UNCHANGED`, `UPDATED`, `FLAGGED_CHANGE`, or a refusal code. A failing record is refused and the rest continue |
| State | Set by the contract's rules in order: the "import everything as not public" setting; a probable duplicate; an individual or entrepreneur; an organisation (live, labelled, noindex) |
| Undo | Removes records created by the batch that are still unreviewed, reverts unreviewed updates, keeps reviewed records |
| Result and audit | Writes the result for acquisition and an audit row: person, batch, file hash, counts, states set |

## Business rules

- **What is imported must be what was drafted.** The content hash is recomputed in RFC 8785 canonical JSON and must match (REQ-221).
- **The suppression list always wins.** A suppressed person or organisation is skipped, and the check runs against the live list.
- **Allowlist only.** Unknown or forbidden fields are refused, never stored.
- **Reviewed fields are never overwritten.** A source change on a reviewed field becomes `FLAGGED_CHANGE` on the review queue.
- **Taxonomy values are the site's.** Unknown terms go through a mapping step before apply.
- **Slugs are generated by the site** from the name with a collision suffix. The record id maps to the post id.
- **A related organisation shows only if it is public.** A person's current-organisation link resolves at read time.
- **The "import everything as not public" setting** is Administrator-only, stored in settings and audited. It stays on until the launch safeguards pass.
- **Personal data in files.** Files are encrypted at rest, logged and deleted after a retention period.
- **Photographs of real people are personal data.** They are used as supplied; there is no background-removal step.
