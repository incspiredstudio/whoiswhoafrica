**Tags.** SPECIFIED: the brief or `docs/requirements.md` names the page, screen or flow. IMPLIED: needed to make a named thing work, but never stated.

**Where.** Every row has a route in the clickable prototype (`/prototype`, hash routing). Staff screens preview flows only (there are no owner, nominee or judge accounts, D-034); the real admin will be WordPress (D-031).

**Totals.** 123 entries: 94 SPECIFIED, 29 IMPLIED. Some entries are states of one screen (modals, empty states, error states); each still has its own row so none is forgotten.

**Fidelity.** `high`: built on the design system in `prototype/theme/`, looks like the final site (72 entries). `wireframe`: staff screens that keep the wireframe look on purpose (46). `tool`: prototype tools (5). See docs/design-direction.md and docs/design-system.md.

**WordPress screen type (D-053).** `native`: a core WordPress screen or a page/post template, shown only for illustration. `customised-native`: a core screen or template with plugin-added columns, filters, fields, actions or a custom post type. `custom`: a screen or page the plugin builds. Public pages are tagged by how WordPress builds them: a plain content page is `native`, a template over profiles or posts is `customised-native`, a form or signed-link page is `custom`. Counts: 12 native, 45 customised-native, 61 custom, 5 n/a (wireframe tool).

**Recommendation.** `Remove from wireframe: WordPress provides it`, `Keep as illustration only`, or `Keep: custom`. Staff screens that WordPress already provides are shown in the wireframe only so the flows can be walked; the real build does not design them.
