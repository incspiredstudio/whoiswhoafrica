# site/

The WordPress website code for WHOISWHO. See `docs/architecture.md` and `docs/build/` for the design, and the GitHub issues (milestones M0 to M5) for the plan.

## Install

```
composer install
npm ci
```

Copy `.env.example` to the secrets file yourself (agents never read `.env*`). Local environment: see issue M0-INF-02.

## Commands

| Task | Command |
|---|---|
| Tests | `composer test` (one test: `composer test -- --filter REQ_208`; architecture: `composer test -- --testsuite Arch`) |
| Style | `composer lint` |
| Static analysis | `composer analyse` |
| Dependency audit | `composer audit` and `npm audit --audit-level=high` |
| Build assets | `npm run build` |
| End to end | `npx playwright test` |

## Who owns what

| Area | Paths |
|---|---|
| plugin | `wp-content/plugins/whoiswho-core/**`, `wp-content/mu-plugins/**`, `bin/`, `tests/Unit`, `tests/Integration`, `tests/Arch` |

## Local environment

Main path (no Docker): WordPress Studio, which bundles PHP 8.3.

```
powershell -File deploy/local/setup.ps1
```

This creates a Studio site in `.studio/` (git-ignored), links `whoiswho-core` and both themes into it, sets pretty permalinks and activates the child theme once it exists. The Administrator password is generated by Studio and printed once; it is never committed. Stop and start with `studio stop|start --path .studio`.

Optional path with Docker: `npx wp-env start` using `.wp-env.json` (core, a separate test environment, `WP_DEBUG` on). Needs Docker Desktop running.

Known gaps, tracked for a later issue: Studio uses SQLite, so PHPUnit integration tests that need MariaDB run in CI or with wp-env; there is no mail catcher on the Studio path (use Mailpit, or read mail from `wp_mail` logs, until one is wired).

Playwright runs against the local URL: set `BASE_URL` to the address Studio prints (default `http://localhost:8882`).

## Adding a third-party plugin

Plugins are installed by Composer from wordpress.org (through wpackagist) and are never committed: `wp-content/plugins/*` is git-ignored except `whoiswho-core`. Core, plugins and themes are pinned to exact versions in `composer.lock`, and file modification is disabled in production, so wp-admin cannot update them.

1. Name the job the plugin does and check `docs/plugins/third-party.md`; prefer a small custom plugin if the job is narrow.
2. Record what personal data it touches, and its visibility matrix (what it exposes publicly).
3. Add it pinned: `composer require wpackagist-plugin/<slug>:<exact version>`.
4. Commit `composer.json` and `composer.lock`; record the plugin in `docs/plugins/third-party.md`.
5. Update it only locally, test, then commit the new lock.

Plugins that are not on wordpress.org are unsupported; vendor them as a private composer package if one is ever needed.

## Assets

`npm run build` runs `build/build.mjs` (esbuild): entries come from `build/entries.json`, output goes to the git-ignored `dist/` with content-hashed names and `dist/manifest.json` for cache-busting. `npm run build:sample` builds the bundled sample. `npm run lint:js` and `npm run lint:css` use ESLint 9 and Stylelint; jQuery and `eval` are errors.

## End-to-end tests

`npx playwright test` runs `tests/e2e` against `BASE_URL` (default http://localhost:8882) at widths 360, 768, 1280 and 1600 plus a WebKit mobile profile, with axe checks (`expectNoA11yViolations`). Set `WIW_THEME_READY=1` once the child theme is active to include the home page. The staff-login helper needs `WIW_E2E_TEST_MODE=1`, a local URL and `E2E_USER`, `E2E_PASS`, `E2E_2FA_CODE`; it refuses otherwise. Reports and traces are written to `playwright-report/` and `test-results/` (CI artifacts).
